# 排课条目停排（disabled）PRD

> 文档日期：2026-08-01

## 1. 背景

当前 `schedule-students-manage.html` 只能维护排课条目的时间、平台、课程与星期。当学生因长期生病等原因暂停上课时，只能删除条目或逐日标记请假：

- 删除条目会丢失该学生原本的排课周期，后续恢复时需要重新配置。
- 按天请假适合临时缺课，不适合“长期停排但保留周期”的场景。

## 2. 目标

- 支持对单个排课条目做“停排/启用”切换。
- 停排后仍保留原有周期、时段、课程和平台配置，便于后续一键恢复。
- `schedule.html` 的今日、明日、本周视图对停排条目统一灰显。
- 停排条目不计入“应上”统计，不参与排课提醒/通知等日常操作。

## 3. 设计决策

### 3.1 数据模型

- 在 `schedule-config.entries[]` 增加布尔字段 `disabled`。
- 缺省值为 `false`，兼容历史配置与本地 override。
- 该字段是“条目级状态”，与现有“按日期请假”状态并存：
  - `disabled = true`：长期停排，保留周期。
  - `cancelled`：仅某一天请假。

### 3.2 管理页交互

- 在 `schedule-students-manage.html` 表格中新增“状态”列。
- 每条记录显示：
  - `正常`：当前启用。
  - `已停排`：当前 disabled。
- 在操作列新增快捷切换按钮：
  - 启用状态时显示 `停排`
  - 停排状态时显示 `启用`
- 切换后立即写入 `schedule-config-override-v1`，无需二次编辑表单。

### 3.3 课表页交互

- 今日/明日列表：
  - disabled 条目保留展示，但整体灰显并沉底。
  - 状态文案显示 `已停排`。
  - `标记请假`、`申请排课`、`发送通知` 等操作按钮禁用。
- 本周视图：
  - disabled 条目灰显，状态文案显示 `已停排`。
- 统计口径：
  - disabled 条目不计入应上分钟数。
  - 仍单独显示停排数量，便于核对。

## 4. 非目标

- 不新增后端存储。
- 不改动临时加课的数据结构。
- 不把 disabled 扩展到学生级全局状态；本期只处理“排课条目级”停排。

## 5. 验收标准

- AC-01：管理页可对单条排课记录执行停排与启用切换。
- AC-02：刷新页面后，disabled 状态仍能从本地 override 正确恢复。
- AC-03：`schedule.html` 今日/明日/本周中 disabled 条目均灰显。
- AC-04：disabled 条目不计入今日、明日、本周“应上”统计。
- AC-05：disabled 条目恢复启用后，课表恢复正常显示与统计。
