# BFD 工资 CSV 学生名单过滤 PRD

- 文档日期：2026-09-26
- 版本：v0.3（已确认）
- 影响页面：`index.html` 工资统计

## 1. 结论

BFD 工资 CSV 的“学生总计”不再展示当前设备收集到的全部学生姓名，只展示所选统计范围内实际产生 BFD 工资的学生。

学生满足以下任一条件时进入“学生总计”：

1. 所选范围内存在 `platform=baifendii` 的有效正课记录，且正课时长大于 0。
2. 所选范围内存在有效 BFD 额外抗遗忘复习计费记录。

不新增手工维护的“当前 BFD 学生白名单”，也不依赖某一台电脑的当前学生列表。姓名仍统一执行别名归一化。

## 2. 背景

当前 2026 年 9 月 BFD 工资 CSV 中，“学生总计”除了实际有工资的学生，还出现大量工资、课时和复习次数均为 0 的姓名，包括：

1. 非 BFD 平台学生。
2. 已退学并加入隐藏名单的学生。
3. 当前设备历史 localStorage 中残留、但本月没有 BFD 工资记录的学生。

截图中实际有工资的学生只有张舒睿、杨开迪，但汇总区仍展示了多名 0 元学生，增加核对成本并容易造成名单误判。

## 3. 根因

工资导出当前会合并三个姓名来源：

1. 当前平台的排课/自定义学生列表。
2. 浏览器内全部 `*_classStatistics` 历史存储键。
3. BFD 额外复习计费账本中的姓名。

代码在校验月份和平台记录之前，先为上述每个姓名创建 0 值汇总对象。后续虽然会过滤非当前平台的正课记录，但没有移除未产生工资的初始对象，因此这些姓名最终仍进入文本摘要和 CSV“学生总计”。

## 4. 目标

1. BFD 九月工资 CSV 只显示当月实际有 BFD 工资的学生。
2. 非 BFD 记录不能使学生进入 BFD 汇总。
3. 已退学/隐藏且当月无工资记录的学生不显示。
4. 不同电脑保存的当前学生名单不同，不影响同一份工资数据的输出名单。
5. 已真实发生的历史工资不能因学生后来退学或被隐藏而丢失。
6. 不改变正课工资、额外复习工资和总工资金额。

## 5. 非目标

1. 不同步不同电脑之间的学生名单或 localStorage。
2. 不在本期新增 BFD 学生白名单管理界面。
3. 不删除历史 `*_classStatistics`、隐藏名单或复习计费账本。
4. 不修改 BFD 正课单价、额外复习 3/5/8 元档位及日期范围规则。
5. 不改变 index 页学生下拉框的展示规则。

## 6. 业务规则

### 6.1 工资学生集合

工资学生集合必须由已经通过以下校验的“工资事件”反向生成：

- 日期属于所选统计范围。
- 正课记录平台等于当前选择的平台。
- 正课时长大于 0，或额外复习计费记录有效。
- 姓名经过 `StudentNameAlias.normalizeStudentName(...)` 归一化。

当前学生名单、隐藏名单和历史存储键只用于发现候选数据，不直接决定 CSV 是否出现该学生。

### 6.2 已退学/隐藏学生

- 已退学/隐藏且所选范围内没有有效工资事件：不显示。
- 已退学/隐藏但所选范围内存在已完成正课或有效额外复习：必须显示真实姓名并计薪，姓名后追加 `（已退学·当月有工资）`。

该规则优先保护历史工资完整性，避免通过修改当前名册删除应付工资。

### 6.3 非 BFD 学生

- 只有李校来啦、麦穗英语等其他平台记录：不显示在 BFD 报表。
- 同名学生同时存在多个平台记录：BFD 报表只计算 BFD 记录。
- 没有 `platform` 的旧正课记录继续按默认平台处理，不进入 BFD 报表。

### 6.4 输出一致性

以下两个区域必须使用同一个过滤后的学生汇总结果：

1. 页面生成的文本工资摘要。
2. 下载 CSV 的“学生总计”。

正课明细、BFD 额外抗遗忘复习明细、课程类型汇总和工资总计保持现有结构。

## 7. 验收标准

| 场景 | 输入 | 预期 |
|---|---|---|
| 当前 BFD 有两名学生产生工资 | 张舒睿有正课，杨开迪有复习工资 | 学生总计只显示张舒睿、杨开迪 |
| 非 BFD 学生有历史正课 | 记录平台为李校来啦或麦穗英语 | BFD 明细和学生总计均不显示 |
| 黑名单学生本月无记录 | 姓名存在历史 key 或隐藏名单 | 不显示 |
| 黑名单学生本月有已完成 BFD 正课 | 当月存在有效 BFD 正课记录 | 显示真实姓名及 `（已退学·当月有工资）`，并正常计薪 |
| 只有 BFD 额外复习 | 无正课，有有效复习计费记录 | 显示该学生，正课为 0，复习费用正确 |
| 同名跨平台 | 同一标准名有 BFD 和非 BFD 记录 | 只计算 BFD 部分，且只显示一行 |
| 跨电脑当前名单不同 | 工资事件数据相同、当前名单不同 | 导出学生总计一致 |

## 8. 风险与约束

1. 工资数据仍保存在当前浏览器，另一台电脑若缺少工资事件本身，无法生成相同金额；本需求只消除“当前名单差异”对输出学生集合的干扰。
2. 不能直接按隐藏名单删除工资记录，否则可能漏发已退学学生在统计期内已完成课程的工资。
3. 不能只按 `工资合计 > 0` 判断，因为未来可能出现有效但金额为 0 的特殊记录；本期以“正课时长大于 0 或有效复习次数大于 0”为事件条件。

## 9. 确认结论

2026-09-26 已确认：

1. 黑名单只控制当前学生选择，不直接删除历史工资。
2. 黑名单学生若在所选月份确有有效 BFD 工资事件，仍保留在工资报表中。
3. 不建立“当前 BFD 仅两人”的静态名单，避免换电脑或学生变动后重复维护。
4. 黑名单学生当月有工资时保留真实姓名，并追加压缩状态文案 `（已退学·当月有工资）`。
