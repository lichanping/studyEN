# PRD：课后复习方式截止时间按北京时间动态计算

## 背景

当前正式课页面与阅读课页面的“课后复习方式”按钮，输出文案中的截止时间固定为：`⏰ 截止：今晚22:20前`。

该实现存在明显问题：

1. 截止时间与实际下课时间脱钩。
2. 晚课场景下，家长和学员可能只剩极短时间完成打卡。
3. 文案固定写死，不能反映当前系统北京时间。

典型问题示例：

1. 若老师晚上 22:00 左右才下课，按钮仍输出 `今晚22:20前`。
2. 这意味着只剩约 20 分钟完成打印、书写、拍照、发群打卡，体验不合理。

## 目标

将“课后复习方式”按钮中的截止时间，从固定文案改为按当前系统北京时间动态计算，避免晚课场景下截止时间过近。

## 范围

本次仅覆盖以下页面中复用 `commonFunctions.selfReviewClick` 的入口：

1. 正式课页面 [index.html](index.html)
2. 阅读课页面 [class-read.html](class-read.html)

本次不包含：

1. 体验课页面独立的“课后复习方式”文案
2. 其它通知、提醒或打卡文案

## 现状

当前实现位于 [commonFunctions.js](commonFunctions.js) 的 `selfReviewClick`。

现状文案核心片段：

```text
⏰ 截止：今晚22:20前
```

当前问题本质上是：截止时间没有读取任何运行时时间，也没有经过计算。

## 需求

### 1. 动态截止时间规则

按钮点击时，系统必须基于“当前系统北京时间”生成截止时间。

建议规则如下：

1. 基准截止时间仍为“当天 22:20”。
2. 若当前北京时间距离当天 22:20 仍有至少 2 小时，则继续显示当天 22:20。
3. 若当前北京时间距离当天 22:20 不足 2 小时，则自动顺延为“当前北京时间 + 2 小时”。
4. 若顺延结果跨到次日凌晨，则不输出凌晨截止时间，统一钳制为“明天 10:00 前”。

这样可同时满足两个目标：

1. 对大多数正常上课场景，仍保持原有“当晚完成”的业务习惯。
2. 对晚课场景，保证至少预留合理完成窗口，不再出现只剩 20 分钟或凌晨打卡的情况。

### 2. 北京时间口径

截止时间计算必须显式使用北京时间口径，而不是隐式依赖设备本地时区。

要求：

1. 计算逻辑需以 `Asia/Shanghai` 为准。
2. 不允许因设备处于海外时区、浏览器时区异常、系统时区误设而生成错误截止时间。

### 3. 文案输出规则

截止时间文案需要根据结果动态输出，禁止继续写死 `今晚22:20前`。

建议输出格式：

1. 当截止时间仍在当天：`⏰ 截止：今晚 HH:mm 前`
2. 当截止时间跨到次日零点后：`⏰ 截止：明天 10:00 前`

示例：

1. 当前北京时间 `2026-08-18 19:30`，输出：`⏰ 截止：今晚22:20前`
2. 当前北京时间 `2026-08-18 21:10`，输出：`⏰ 截止：今晚23:10前`
3. 当前北京时间 `2026-08-18 22:00`，输出：`⏰ 截止：明天10:00前`
4. 当前北京时间 `2026-08-18 23:35`，输出：`⏰ 截止：明天10:00前`

### 4. 文案其余部分保持不变

除截止时间这一行外，以下内容本次不改：

1. 笔头作业说明
2. 口头作业说明
3. 21 天抗遗忘复习规则
4. 结尾鼓励语

## 交互要求

1. 用户点击“课后复习方式”按钮。
2. 系统实时读取当前北京时间。
3. 系统按动态规则生成截止时间文本。
4. 完整文案继续执行：
   - 复制到剪贴板
   - 弹窗展示

## 技术要求

### 1. 推荐实现方式

在 [commonFunctions.js](commonFunctions.js) 中新增独立 helper，例如：

1. `getBeijingNow()`
2. `resolveSelfReviewDeadline(now)`
3. `formatSelfReviewDeadline(deadline)`

然后由 `selfReviewClick()` 统一拼接最终文案。

### 2. 代码约束

1. 不要把动态截止时间逻辑散落到多个页面。
2. 仍以 [commonFunctions.js](commonFunctions.js) 作为唯一文案与规则源。
3. 正式课页与阅读课页继续共用同一套逻辑。

## 验收标准

| 场景 | 当前北京时间 | 预期截止文案 |
|---|---|---|
| 常规晚间课 | 2026-08-18 19:30 | 今晚22:20前 |
| 接近既定截止 | 2026-08-18 21:10 | 今晚23:10前 |
| 晚课 22 点下课 | 2026-08-18 22:00 | 明天10:00前 |
| 深夜课 | 2026-08-18 23:35 | 明天10:00前 |
| 非北京时间设备 | 设备本地非东八区 | 仍按北京时间计算 |

## 测试建议

至少补以下自动化覆盖：

1. helper 在“今晚 22:20 仍足够远”时返回固定 22:20。
2. helper 在“距离 22:20 不足 2 小时”且未跨日时返回 `当前北京时间 + 2 小时`。
3. helper 在跨日场景下统一输出 `明天10:00前`。
4. [tests/test-read-trial-platform-ui.js](tests/test-read-trial-platform-ui.js) 需要从“整段固定文案匹配”调整为“校验动态截止时间生成逻辑已接入正式课/阅读课入口”。

## 非目标

本次不处理以下问题：

1. 是否根据具体学员年龄、课程类型进一步区分截止策略
2. 是否把截止时间改成可配置后台参数
3. 是否把体验课页面也改成同一策略

## 风险与注意事项

1. 现有测试中有对完整固定文案的强匹配，修改前需要同步调整测试。
2. 若直接使用浏览器本地时间对象而不处理时区，容易在非北京时间环境下产生偏差。
3. 跨日场景下，文案不能继续显示“今晚”，必须切换为“明天”，且不能落在凌晨。
