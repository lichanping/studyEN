## 结论

复用首页和现有月末总结模块。登记和删除沿用请假记录的简单行为，新记录只存平台、归一化学生姓名、正课日期。“未交作业统计”与月末披露复用同一数据源及去重筛选函数。

报告新增纯文本披露块，并在原报告生成完成后统一前置拼接，避免遗漏零数据提前返回分支。所有输出共用同一个最终字符串。

实现复用现有业务模块及测试文件，不新增业务依赖、页面或数据服务。

## 目标与边界

只增加人工按正课日期登记、查询、删除、独立统计和月末披露。不增加补交/作废状态、作业摘要或审计功能，不自动判断作业是否完成。

沿用当前平台选择的优先级：页面 `platformSelect` 优先，缺失时再读取现有平台配置。平台显示名不用于主键，防止名称调整破坏隔离。打开弹窗时冻结平台/学生上下文，保存和状态操作前再次核对。

不重构旧请假、课堂和抗遗忘数据源；新披露的平台隔离不意味着旧月末总结的所有历史数据已经完成跨平台迁移。

## 数据结构

拟新增 key：`homework-review-incomplete-v1`。不存在的 key 代表尚无记录，不回填历史事实；上一版复杂结构尚未部署，无需迁移。

```json
{
  "version": 1,
  "records": [
    {
      "platformId": "baifendii",
      "studentName": "杨开迪",
      "classDate": "2026-10-01"
    }
  ]
}
```

约束：

- `platformId` 使用现有配置的规范平台 ID；`studentName` 为归一化完整姓名，不用报告中的简写称呼。
- `classDate` 为用户输入的对应正课本地日历日期 `YYYY-MM-DD`，校验真实日期并拒绝未来日期，不用 `toISOString().split('T')[0]` 获取业务日期。
- 唯一键为 `(platformId, studentName, classDate)`。同日重复保存仍一条，删除按唯一键过滤，不按数组下标操作。
- 不强制要求本机课堂统计中存在该正课日期，同一天多节正课仍只登记一次。
- 删除直接写回剩余记录，不保留历史副本。是否登记、何时删除由用户控制。
- 不存摘要、备注、处理状态、录入时间或补交时间。

### 读取、写入与失败处理

在模块内分离读取校验、同日去重保存、精确删除和范围筛选，便于独立测试。

1. key 不存在：返回空记录集合。
2. JSON 损坏、版本不支持、结构或字段非法：明确报读取异常，不覆盖原数据，不静默跳过后假装零记录；阻止生成可能遗漏披露的报告。
3. 保存前重新读取，以唯一键去重后保存，不使用打开弹窗时的旧数组直接覆盖。
4. 删除前重新读取，仅移除目标平台、学生、日期；写入成功后刷新列表。
5. 写入异常时保留表单或列表，不提示成功。沿用本机单用户方式，不增加并发协作流程。

## 交互设计

### 入口与登记

拟使用 `recordIncompleteHomeworkButton`、`viewIncompleteHomeworkRecordsButton` 作为登记和查看按钮 ID，文案为“记录未交作业”“查看未交记录”，紧接查看请假记录。

沿用现有弹窗结构，唯一可输入字段为“正课日期”，使用日期控件且默认当天。按钮在窄屏可换行，弹窗可滚动。

显示平台和学生只读上下文。保存时若首页平台或学生改变，拒绝提交，提示关闭后重新打开；取消只关闭，不触发写入。

### 查看与处理

展示当前平台、当前学生的全部日期记录，每条为“YYYY-MM-DD 正课”和删除按钮。不增加状态和筛选控件。

点击删除直接移除该条并刷新列表，与请假记录一致，不新增确认、原因或历史保留流程。更正日期采用删除后重新登记。

平台、学生、日期采用安全 DOM API 展示；报告提示中的学生姓名安全处理，防止 HTML 注入。

## 未交作业统计接入

拟新增 `incompleteHomeworkStatsButton`，文字“未交作业统计”，在首页数据统计区紧接 `downloadFileButton`，位于正课统计之前。事件绑定到月末总结模块导出的独立统计函数。

1. 冻结当前平台和学生，校验已选择学生。
2. 复用 `getStatsDateRangeSelection` 读取现有按天/按月控件；按天包含今天，按月为所选自然月，不新增日期控件。
3. 将范围边界转换为本地日历日期，按 `classDate` 闭区间筛选，去重后正序排列。
4. 复用下文共用筛选/汇总函数，构建包含范围、总次数、所有对应正课日期的纯文本。
5. 沿用统计报告惯例，自动复制、下载 TXT 和提示；同一字符串供三种输出使用。文件名拟为 `${userName}_${startDate}_${endDate}_未交作业统计.txt`，日期为本地 `YYYY-MM-DD`。
6. 零记录仍生成 0 次报告，明确“所选范围暂无登记记录”，不推断所有作业都已完成。读取损坏数据则提示失败，不能降级为 0 次。

独立统计和月末总结统一在汇总行说明未提交次数及“对应正课日期”，编号明细仅输出 `YYYY-MM-DD`，不逐行重复“正课的课后复习未提交”。平台仅用于内部存储隔离和筛选，不写入分享正文、复制内容、TXT 内容或文件名，不显示平台名称、平台 ID 或多平台提示。

统计为只读操作，不写入或删除记录，复用原有日期范围规则而不修改其他统计按钮。

## 月末总结接入

### 筛选与汇总

提供共用、可测试的筛选/汇总函数，输入为记录、平台 ID、归一化学生姓名和起止日历日期，输出为去重正课日期列表及总次数。独立统计传入现有 helper 的范围，月末总结传入所选自然月的范围。

- 按平台、学生及 `classDate` 筛选，边界包含首尾日期。
- 同一天对应一次未提交，总次数等于去重日期数，不区分处理状态。
- 跨月补录按正课月份归属，不按登记月份；删除后重新生成时次数和日期同步减少。
- 不强制关联课堂统计，不用姓名缩写、当前日期或生成时间代替筛选键。
- 日期明细正序呈现。相同平台、学生、月份下，独立统计和月末总结必须一致。

### 统一输出路径

在 `generateMonthlySummary` 开始时冻结学生、平台和月份。在异步读取抗遗忘统计之后仍使用这份上下文；如选择已经变化，终止并提示重新生成，避免混合不同选择的数据。

拟采用：

```text
baseReport = 原 buildMonthlySummaryReport 的完整结果
disclosure = 当前平台、学生、正课月份的未交记录披露块
report = 有记录 ? disclosure + 空行 + baseReport : baseReport
```

前置拼接在 `buildMonthlySummaryReport` 返回之后、剪贴板和 Blob 构造之前执行。这样零数据提前返回的结果也经过同一处理，无记录时原报告逐字符不变。

披露包含完整姓名、月份、未提交总次数及所有对应正课日期，不显示平台名称、平台 ID 或多平台提示。平台仍保留为内部筛选条件，不进入面向家长的分享正文、复制内容、TXT 内容或文件名。不增加作业摘要或状态，汇总行示例为“本月未提交课后复习作业共 2 次，对应正课日期：”，明细仅列“1. 2026-10-01”等日期。

月末总结“预览数据”采用同一筛选和汇总函数，在预览数据顶部显示披露摘要及明细；预览与 TXT 不另写两套统计规则。

复制、TXT 下载和提示使用同一个最终 `report`。提示展示时安全处理 HTML，不新增一份不同口径的专用报告，不改变文件命名规则。

### 现有点评冲突

已确认：有当月未交登记时，只抑制那条依据 `totalDuration >= 8` 推导“课后能主动打卡”的闪光点，其他课堂与复习统计规则不改；无登记时沿用原点评。没有记录也不能据此推导“作业全完成”，本期不建立作业完成率模型。

## 风险与回滚

- 本机数据可丢失、可修改或直接删除，没有验证操作者身份；不承诺长期保管、防篡改或完整历史追溯。
- 教练负责核对记录事实，工具不根据未收到打卡直接断言学生从未做过作业。
- 旧数据不回填，旧请假、课堂数据的平台隔离问题不随本期自动修复。
- 回滚只撤除新增入口、文案和报告拼接，不清理新 localStorage key，防止丢失已登记数据。
- 若确需云端共享或防静默修改，需要单独评审后端持久化、认证、访问控制、审计及备份，不能作为隐含附加需求实现。
