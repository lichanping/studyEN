# BFD 抗遗忘复习额外计费与月工资统计 PRD

文档日期：2026-09-20
版本：v0.2（MVP 评审稿）

## 0. 结论

该需求在现有纯前端、本地存储架构内可实现，不需要新增后端接口。

推荐方案是在抗遗忘页仅为百分缔（以下简称 BFD）显示“本次 BFD 抗遗忘复习需要额外计费”复选框，按“BFD + 标准学生名 + 北京时间日期”保存每天最后一次提交的结构化计费结果；正课页生成工资统计时，把所选日期范围内的 BFD 正课工资与额外复习费用合并汇总，并在 CSV 中单独输出复习计费明细。

方案不修改 BFD 正课 `48 元/小时` 的现有口径，也不影响李校来啦、麦穗英语及未勾选的 BFD 复习记录。

## 1. 背景

即将在 BFD 新增一名学员。该学员前期只参加抗遗忘复习，复习需要按每次完成的复习词数额外结算；开始上正式课后，抗遗忘复习免费，收入包含在 BFD 正课 `48 元/小时` 中。

当前系统存在以下限制：

1. `anti-forgetting.html` 只保存复习正确率等反馈数据，没有工资计费标记和结构化计费记录。
2. 抗遗忘反馈按学员、日期覆盖，不能直接作为“每次复习”的工资账本。
3. `index.html` 的工资统计只读取各学员的 `${userName}_classStatistics` 正课记录。
4. 正课工资 CSV 没有额外抗遗忘复习的次数、词数、档位和费用明细。
5. 学员统计存储键未按平台隔离；同名学员可能在一个统计键内出现多个平台的课程记录，因此 BFD 工资统计必须按记录平台再次过滤。

## 2. 目标

1. 老师可以在抗遗忘页明确标记“本次 BFD 抗遗忘复习需要额外计费”。
2. 系统按本次总复习词数自动计算额外复习费用。
3. 同一 BFD 学员在同一北京时间日期重复生成反馈时，以最后一次提交覆盖，不重复累计费用。
4. 正课页选择 BFD 后，可按所选统计范围汇总所有 BFD 学员的正课工资和额外复习费用。
5. 工资 CSV 单独列出每笔额外复习的学员、时间、词数、计费档位和金额，便于核对。
6. 未勾选的 BFD 复习不产生额外费用；BFD 正课继续按 `48 元/小时` 计算。
7. 其他平台的页面行为、工资口径和历史数据保持不变。

## 3. 范围

### 3.1 In Scope

1. `anti-forgetting.html` 增加 BFD 专属的单次复习计费复选框。
2. 旧版“抗遗忘课堂反馈”和“新版反馈”统一写入同一种 BFD 复习计费记录。
3. 使用本地结构化账本保存额外复习计费记录。
4. `index.html` / `classFormal.js` 工资统计合并 BFD 正课工资与额外复习费用。
5. 工资文本摘要和 CSV 增加额外复习次数、费用及逐笔明细。
6. 补充计费边界、幂等、跨平台隔离和工资汇总自动化测试。

### 3.2 Out of Scope

1. 不修改 `schedule.html` 的“按实际上课生成工资统计”；该页面当前不支持 BFD 工资统计。
2. 不新增后端、云端同步或跨浏览器同步。
3. 不自动判断学员是否已经开始上正课；本期按每次复习的 checkbox 明确决定是否额外计费。
4. 不迁移或反推历史抗遗忘反馈的费用；功能上线前的历史记录默认不计入。
5. 不修改 BFD 正课、阅读课、体验课的现有单价。
6. 不新增工资账本编辑、手工取消或历史补录入口。
7. 不为“按天”和“按月”实现两套工资内容逻辑；两种模式只提供不同的日期范围。

## 4. 业务规则

### 4.1 计费资格

一笔抗遗忘复习同时满足以下条件时，才计入额外复习工资：

1. 当前平台为 `baifendii`。
2. 老师勾选“本次 BFD 抗遗忘复习需要额外计费”。
3. 已选择有效学员和复习时间。
4. 本次总复习词数为正整数。
5. 点击“抗遗忘课堂反馈”或“新版反馈”并完成提交。

未勾选时不产生额外费用，学员正课仍按原有 BFD 单词课 `48 元/小时` 计算。

### 4.2 复习词数口径

额外计费必须复用“抗遗忘课堂反馈”按钮的现有词数口径。实现时把现有求和提取为唯一的共享函数，由旧版反馈、新版反馈和计费逻辑共同使用；计费模块不得再次读取 DOM 或另写一套求和逻辑。共享函数返回的 `antiForgettingReviewWord` 口径是：

```text
总复习词数 = 所有可见/已填写的复习词数输入框之和
           + 重点语言点非空行数
           + 语言闯关非空行数
```

不使用“遗忘词数”“正确词数”或正课新词数计算费用。

勾选额外计费后，如果总复习词数为 `0`、为空、负数或包含无法解析的值，则不得写入计费记录，并提示老师修正词数或取消勾选，避免静默漏算或错算。

多个复习词数输入框必须逐项校验为非负整数后再求和，不能让旧版、新版反馈对非法输入采用不同处理方式。

### 4.3 计费档位

本评审稿建议按从高到低匹配阈值：

| 本次总复习词数 | 单次费用 | 档位标识 |
| --- | ---: | --- |
| 1-99 词 | 3 元 | `1-99` |
| 100-199 词 | 5 元 | `100-199` |
| 200 词及以上 | 8 元 | `200+` |

计算函数必须为纯函数，输入总复习词数，输出档位与金额；UI 保存和工资统计不得各自复制一套判断逻辑。

### 4.4 次数与重复提交

1. 同一平台的同名学生在同一北京时间日期只存在一条复习计费结果，次数固定为 `1`。
2. 使用“`baifendii` + 学员标准名 + 北京时间日期”作为业务唯一键。
3. `reviewTime` 按北京时间解释，业务日期直接取输入值的 `YYYY-MM-DD`，不得先转 UTC，也不得依赖设备当前时区换算。
4. 同一天先后点击旧版、新版反馈，重复点击同一按钮，或修改词数后再次提交，都以最后一次有效提交覆盖当天记录。
5. 最后一次提交勾选 checkbox 时，保存最新词数、档位和金额；最后一次提交未勾选时，移除当天已有的额外计费结果。
6. MVP 不提供二次确认、独立取消按钮或计费记录管理入口。
7. 只有日期确认、词数校验和反馈生成均成功后才能同步计费账本；用户取消日期确认、计费词数非法或反馈流程中止时，原有当天记录保持不变。

## 5. 页面交互

### 5.1 抗遗忘页

在复习词数区域增加 checkbox：

```text
□ 本次 BFD 抗遗忘复习需要额外计费
```

交互规则：

1. 仅当平台选择器的内部值为 `baifendii` 时显示；切换到任何其他平台后立即隐藏、取消勾选，并强制视为不计费。
  - `platform !== 'baifendii'` 时：计费控件容器 `hidden = true`、checkbox `checked = false`，计费保存函数直接拒绝写入。
2. 新平台、新学员或新复习日期默认不勾选，避免把免费复习误计费。
3. 原提示“该页面不涉及工资统计”需改为：仅勾选的 BFD 复习会计入工资统计，其他复习不计费。
4. 两个反馈按钮必须调用同一个词数汇总函数，并把得到的 `antiForgettingReviewWord` 传给同一个计费同步函数。
5. 提交完成后清楚提示本次结果，例如“已记录 BFD 额外复习：86 词，3 元”或“本次复习不额外计费”。
6. `reviewTime` 的默认值必须按 `Asia/Shanghai` 生成，不得直接使用设备本地时区；用户选择的 `datetime-local` 值统一解释为北京时间。

### 5.2 正课页工资统计

老师执行以下操作：

1. 平台选择“百分缔”。
2. 统计方式选择“按天”或“按月”。
3. 输入最近天数或选择月份。
4. 点击“工资统计”。

系统应：

1. 使用现有 `getStatsDateRangeSelection()` 得到统一的开始日期和结束日期。
2. 收集该范围内所有 `platform=baifendii` 的正课记录。
3. 收集该北京时间日期范围内所有有效的 BFD 额外抗遗忘复习计费记录。
4. 即使某学员在所选范围内没有正课、只有额外复习，也必须出现在工资明细和学生汇总中。
5. 同名学员在其他平台的正课或复习记录不得混入 BFD 工资。
6. 正课工资、额外复习费用分别小计后再计入学生总计和工资总计。
7. 现有“无正课则退出”条件必须改为“无 BFD 正课且无有效 BFD 额外复习记录才退出”。

“按天”和“按月”必须走同一套工资聚合逻辑，只将 `getStatsDateRangeSelection()` 返回的日期范围作为筛选条件；两种模式都包含符合范围的额外复习费用。

```text
BFD 按天工资 = 最近 X 天范围内的正课工资 + 同范围内的额外复习费用
BFD 按月工资 = 所选月份范围内的正课工资 + 同范围内的额外复习费用
```

## 6. 数据方案

### 6.1 存储位置

新增 localStorage 键：

```text
bfd-extra-review-fee-ledger-v1
```

选择 localStorage 的原因：

1. 当前正课工资生成是同步读取 localStorage。
2. 无需把 `generateSalaryReport` 改成跨 IndexedDB 的异步流程。
3. 该账本只保存结构化计费元数据，不重复保存遗忘词、发音词等反馈正文。

### 6.2 数据结构

```json
{
  "version": 1,
  "records": [
    {
      "platform": "baifendii",
      "studentName": "同学",
      "reviewTime": "2026-09-20T19:30",
      "reviewDateBeijing": "2026-09-20",
      "totalWords": 86,
      "pricingTier": "1-99",
      "pricingVersion": "bfd-review-v1",
      "feeAmount": 3,
      "updatedAt": "2026-09-20T12:00:00.000Z"
    }
  ]
}
```

字段约束：

| 字段 | 规则 |
| --- | --- |
| `platform` | 固定为 `baifendii` |
| `studentName` | 使用 `StudentNameAlias.normalizeStudentName(...)` 的结果，保存前去除首尾空格 |
| `reviewTime` | 当天最后一次提交的复习时间，仅用于明细展示 |
| `reviewDateBeijing` | 从 `reviewTime` 原始值提取的北京时间日期，用于按日覆盖和日期范围筛选 |
| `totalWords` | 正整数 |
| `pricingTier` | `1-99`、`100-199` 或 `200+` |
| `pricingVersion` | MVP 固定为 `bfd-review-v1` |
| `feeAmount` | 本次费用快照，值为 3、5 或 8 |
| `updatedAt` | 最近一次提交时间，仅用于排查，不参与工资归属月份 |

### 6.3 读取与容错

1. localStorage 键不存在时按空账本处理，不需要迁移。
2. JSON 损坏或 `records` 不是数组时，不得覆盖原始内容；本次工资统计跳过额外费用并给出明确错误提示。
3. 读取时如发现同一业务唯一键有重复记录，只采用 `updatedAt` 最新的一条并提示数据异常；正常写入必须直接覆盖，不能追加重复项。
4. 单条记录字段非法时跳过该条，工资结果提示“发现 N 条无效复习计费记录”。
5. MVP 只识别 `bfd-review-v1`，未知版本告警并跳过；工资统计按该版本和 `totalWords` 重新校验金额，记录中的 `feeAmount` 仅作为快照和核对值。
6. 日期筛选直接比较北京时间 `YYYY-MM-DD` / `YYYY-MM` 字符串，不通过 `new Date(...).toISOString()` 转换，避免跨日或跨月。

## 7. 工资计算方案

### 7.1 正课部分

1. BFD 单词课继续按 `48 元/小时`。
2. 其他课程类型继续使用现有单价函数。
3. 读取 `${userName}_classStatistics` 的每一条记录时，必须执行 `recordPlatform === selectedPlatformId` 过滤，不能只依赖当前平台的学员下拉列表。
4. 历史没有 `platform` 的正课记录继续按默认平台“李校来啦”兼容，不能在 BFD 统计中出现。

### 7.2 额外复习部分

```text
某学员额外复习费用 = 所选北京时间日期范围内有效计费记录 feeAmount 之和
某学员工资总计 = 正课工资 + 额外复习费用
总工资 = 所有学员正课工资 + 所有有效额外复习费用
```

额外复习不增加课时，只增加“复习次数”和“复习费用”。禁止把 3/5/8 元换算为课时，以免污染正课总课时。

### 7.3 学员集合

BFD 工资统计中的学员集合应为以下来源的并集：

1. 当前 BFD 自定义学员和排课学员。
2. 所选范围内存在 `platform=baifendii` 正课记录的学员。
3. 所选范围内存在有效 BFD 额外复习计费记录的学员。

这样即使学员尚未开始正课，或以后从当前排课名单移除，已经发生的应付复习费用仍不会从工资统计中丢失。

上述三个来源中的姓名在合并前都必须经过 `StudentNameAlias.normalizeStudentName(...)`，账本覆盖、工资汇总和 CSV 展示使用同一个标准名，避免别名被算成两个学生。

## 8. 工资明细输出

现有 CSV 的正课明细继续保留，并新增独立区块：

```text
BFD 额外抗遗忘复习明细
学生姓名,复习时间,复习词数,计费档位,次数,费用(元)
同学,2026-09-20 19:30,86,1-99词,1,3
```

学生汇总调整为：

```text
学生姓名,正课总课时,正课工资(元),额外复习次数,额外复习费用(元),工资合计(元)
```

总计区增加：

1. BFD 额外抗遗忘复习总次数。
2. BFD 额外抗遗忘复习费用小计。
3. 包含正课与额外复习费用的工资总计。

文本摘要同步展示上述小计。所有金额统一保留最多两位小数；复习费用当前均为整数。

## 9. 安全与数据完整性

1. **默认不收费**：checkbox 默认不勾选，且非 BFD 平台不能写入该账本。
2. **按日覆盖防重**：相同平台、学员、北京时间日期只允许存在一条记录，最后一次提交覆盖。
3. **姓名统一**：使用现有 `StudentNameAlias.normalizeStudentName(...)` 后再生成唯一键和汇总。
4. **跨平台隔离**：工资统计同时过滤学员来源、每一条正课记录的平台和复习记录平台。
5. **金额不信任页面输入**：页面不提供手工金额输入；金额只由纯计费函数计算。
6. **异常不静默**：账本损坏、字段非法或金额校验失败时显示警告，不把异常数据计入工资。
7. **历史不回算**：没有明确勾选证据的历史复习一律不收费。
8. **北京时间一致**：默认复习时间和业务日期均按 `Asia/Shanghai` 处理，不使用 UTC 或设备时区转换。
9. **CSV 安全**：学生姓名等文本字段进入 CSV 前继续执行引号转义，并对以 `= + - @` 开头的值添加文本前缀，避免表格公式注入。
10. **最小数据保存**：计费账本不保存反馈正文、遗忘词或其他非计费信息。

## 10. 实施拆分（TDD）

### 10.1 第一阶段：计费纯函数与账本

先增加失败测试，再实现：

1. 词数档位边界：`1`、`99`、`100`、`199`、`200`。
2. `0`、负数、非数字拒绝计费。
3. 同一 BFD 学员同一北京时间日期重复保存只保留最后一条并更新金额。
4. 非 BFD 记录无法写入。
5. 损坏账本和非法单条记录安全跳过并返回错误信息。
6. 学员别名标准化后使用同一个按日唯一键。

### 10.2 第二阶段：抗遗忘页交互

先增加失败测试，再实现：

1. checkbox 仅 BFD 显示，默认不勾选。
2. 切换平台、学员或复习日期后 checkbox 重置为未勾选。
3. 两种反馈按钮直接复用各自已计算的 `antiForgettingReviewWord`，多个复习词数输入框及现有自动计数项均只汇总一次。
4. 同一北京时间日期重复点击或先后点击两种反馈，只保留最后一次提交结果。
5. 最后一次未勾选时，当天不产生额外复习工资。
6. 非北京时间设备上，默认日期和按天/按月范围归属仍按 `Asia/Shanghai` 计算。
7. 日期确认取消、词数非法或反馈中止时不改写当天已有计费记录。

### 10.3 第三阶段：工资统计与 CSV

先增加失败测试，再实现：

1. BFD 正课记录按 48 元/小时计算。
2. 未勾选复习不增加工资。
3. 3/5/8 元档位正确进入学生小计和总计。
4. 只有复习、没有正课的 BFD 学员仍出现在报表。
5. 同名其他平台记录不进入 BFD 报表。
6. CSV 包含逐笔复习明细、次数和费用。
7. 空账本、损坏账本、北京时间跨月边界和重复记录均有覆盖。
8. 按天和按月使用同一聚合函数，并分别按各自日期范围计入额外复习费用。
9. 没有正课但有额外复习时不会被“无正课”条件提前退出。

### 10.4 回归测试

至少运行：

## 11. 验收标准

1. 李校来啦、麦穗英语抗遗忘页不展示额外计费 checkbox，也不会产生额外复习工资。
2. BFD 抗遗忘页展示 checkbox，新会话默认不勾选。
3. BFD 复习 1-99 词并勾选后记 3 元；100-199 词记 5 元；200 词及以上记 8 元。
4. 同一平台的同名学员在同一北京时间日期重复生成反馈只计 1 次，并以最后一次提交的 checkbox、词数和金额为准。
5. 当天最后一次提交未勾选时，该日复习不进入工资。
6. BFD 学员开始上正课后，老师保持 checkbox 未勾选，正课按 48 元/小时计算且复习不额外收费。
7. 正课页选择 BFD 后，无论按天还是按月，工资统计都包含所选范围内所有 BFD 学员的正课工资和已勾选复习费用。
8. 只有额外复习、没有正课的 BFD 学员也能生成工资记录。
9. 工资 CSV 可逐笔核对额外复习的时间、词数、档位、次数和金额。
10. BFD 工资结果不包含同名学员在其他平台的记录。
11. 按天与按月除日期范围外使用相同工资口径；历史数据不自动补算，其他平台工资结果无回归。

## 12. 风险与回滚

| 风险 | 控制措施 |
| --- | --- |
| 重复点击反馈导致重复工资 | 按 BFD、标准学生名、北京时间日期幂等覆盖 |
| 开始正课后忘记取消额外计费 | 默认不勾选；每次复习明确选择；恢复已有记录时展示已保存状态 |
| 同名学员跨平台串账 | 正课与复习记录都按 `platform` 过滤 |
| 本地账本被清理 | 在 UI 提示数据仅保存在当前浏览器；本期不提供云同步 |
| 未知费率版本被错误计入 | MVP 只识别 `bfd-review-v1`，其他版本告警并跳过 |
| 坏数据污染工资 | 校验后跳过并显式警告，不静默兜底金额 |

回滚时可隐藏 checkbox、停止写入和读取 `bfd-extra-review-fee-ledger-v1`；现有正课记录与原工资逻辑不需要迁移。保留账本键可避免未来恢复功能时丢失已经确认的计费记录。

## 13. 已确认的 MVP 决策

1. 同一平台的同名学生同一天不存在多次独立复习计费；按北京时间日期保留最后一次提交。
2. 计费词数直接复用“抗遗忘课堂反馈”现有的 `antiForgettingReviewWord` 汇总结果。
3. 不开发独立取消、编辑或历史补录入口。
4. BFD 按天和按月工资统计都包含额外复习费用，两者只在日期范围上不同。
