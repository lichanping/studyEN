# 停排不覆盖排课匹配状态 PRD

> 文档日期：2026-08-01

## 1. 背景

当前 `schedule.html` 在条目被 `disabled` 后，会把今日/明日列表最右侧的排课匹配状态标签也改写成 `已停排`。

这带来一个语义混淆：

- `已停排` 是本地排课条目的维护状态。
- `已排课 / 已完成 / 未排课 / 未获取 / 不检查` 是外部首页排课查询结果。

两者不是同一个维度，不能互相覆盖。

## 2. 目标

- 停排后，条目本身继续灰显，主状态继续显示 `已停排`。
- 但最右侧“是否已排课”的查询标签必须保留真实结果，不被 `disabled` 覆盖。

## 3. 设计

### 3.1 状态分层

- 本地条目状态：
  - 正常
  - 已请假
  - 已停排
- 外部匹配状态：
  - 已排课
  - 已完成
  - 未排课
  - 未获取
  - 不检查

### 3.2 渲染规则

- disabled 行继续：
  - 灰显
  - 禁用操作按钮
  - 主状态显示 `已停排`
- 但 `getCourseScheduleState(entry, dateValue)` 仍照常执行。
- 最右侧匹配标签继续显示真实查询结果，不再强制替换成 `已停排`。

## 4. 非目标

- 不修改停排对课时统计的影响。
- 不修改停排对周视图 mini-status 的展示。
- 不修改查询逻辑本身，只修正 disabled 时的展示覆盖。

## 5. 验收标准

- AC-01：disabled 行主状态显示 `已停排`。
- AC-02：disabled 行最右侧匹配标签仍显示真实查询结果，如 `已排课`、`已完成`。
- AC-03：disabled 行仍保持灰显与按钮禁用。
