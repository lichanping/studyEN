# 排课订阅按钮 Loading 状态 PRD

> 文档日期：2026-08-05

## 1. 背景

当前 `schedule.html` 中，LXLL 未排课条目的"订阅"/"取消订阅"按钮在点击后，按钮仅被 `disabled`，文字不变。由于订阅请求需要调用 Netlify Function 并执行即时检查，耗时可能超过 1 秒，用户无法感知点击是否生效，容易重复点击或产生困惑。

## 2. 目标

- 点击订阅按钮后，立即将按钮文字切换为 "订阅中…"，给用户明确的视觉反馈。
- 点击取消订阅按钮后，立即将按钮文字切换为 "取消中…"。
- 请求成功完成后，由 `onChange()` 重新渲染，按钮显示最终正确状态（"取消订阅" 或 "订阅"）。
- 请求失败时，恢复按钮原始文字，让用户可以重试。

## 3. 设计决策

### 3.1 最小改动原则

仅在现有 `subscriptionButton` click handler 中增加文字切换逻辑，不引入新状态变量或 CSS 类。

### 3.2 文字切换策略

| 场景 | 点击前文字 | 点击后文字 | 成功后 | 失败后 |
|------|-----------|-----------|--------|--------|
| 订阅 | "订阅" | "订阅中…" | onChange() 重渲染为 "取消订阅" | 恢复为 "订阅" |
| 取消订阅 | "取消订阅" | "取消中…" | onChange() 重渲染为 "订阅" | 恢复为 "取消订阅" |

### 3.3 记忆原始文字

在 handler 内用局部变量 `originalText` 保存点击前的文字，失败时恢复。不使用全局状态。

## 4. 影响范围

- `schedule.html`：`renderDayEntries` 函数内 `subscriptionButton` click handler。
- `tests/test-schedule-subscription-ui.js`：新增 loading 状态断言。

## 5. 验收场景

1. 点击"订阅"按钮 → 按钮立即变为"订阅中…"且 disabled → 成功后变为"取消订阅"。
2. 点击"取消订阅"按钮 → 按钮立即变为"取消中…"且 disabled → 成功后变为"订阅"。
3. 网络失败时 → 按钮恢复原始文字，toast 提示错误。
