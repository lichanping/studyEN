# TDD 工作流规范

## 核心规则

- 默认使用 TDD：Red -> Green -> Refactor
- 在添加证明目标行为的失败测试之前，不要编写或更改生产代码

## 必需流程

1. 先定义预期行为
2. 添加或更新一个因正确原因失败的测试
3. 实现最小的生产代码变更使测试通过
4. 在保持测试绿色的前提下安全重构
5. 完成前运行相关测试

## 测试期望

- 优先编写小而聚焦的测试，贴近被改动行为
- 为 bug 修复添加回归测试
- 如果没有现有测试文件，使用项目当前的测试风格新建
- Python 代码优先使用 `pytest` 风格，除非目标区域已使用其他框架
- 排课或配额逻辑变更时，在实施前后都运行 `npm run test:quota`，并报告两次结果
- MCP 驱动的 UI 验证，必须在外部 Chrome 浏览器中通过 Chrome DevTools MCP 启动和检查，不要使用 VS Code 嵌入页面（视口太小）

## 例外策略

- 如果任务无法合理遵循 TDD（例如一次性脚本或纯机械性编辑），说明原因，并尽可能添加验证检查
